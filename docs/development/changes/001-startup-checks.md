# 001：初回設定のHook呼出しと型検査の修正

日付：2026-10-26（日本時間）。状態：人間レビュー前の初実装。目的と検証を結ぶ最初の変更単位。ブランチ公開以降の状態は開発の入口と実際のGit／PRで確認する。

## 今回の定義

- 困る人・場面：初めてプロフィールを設定する利用者には、安定して開始画面を開ける必要がある。開発者には、通常の品質確認で既知のエラーが残り、別の問題を見分けにくい状況がある。
- 変える振る舞い：start画面のuseRouterをコンポーネント内で呼び、ReactのHook規約に沿わせる。2つのimportから.tsx拡張子を外し、通常のTypeScript検査を通せるようにする。実端末での障害発生は未再現であり、再現済みクラッシュの修正とは表現しない。
- 受け入れ条件：Lintエラー0件、通常の`tsc --noEmit`成功、Androidバンドル生成成功。画面遷移先・保存処理・依存宣言に変更がないことを差分で確認する。
- 含めない範囲：UIの再設計、警告の一括修正、プロフィール保存の障害対応、AI機能、データ移行、CI追加、リモート操作、公開。
- 影響：利用者データ・DBスキーマ・保存キーは変更しない。start画面の操作と見た目は変更せず、Hook取得の時機だけを修正する。既存の型検査回避オプションが不要になる。

## 選択肢と決定

Hookエラーを抑制する方法は採らず、HookをReactコンポーネント内に移す。Expo Routerのmodule-level routerに置き換える選択肢もあるが、既存のuseRouterを使い、差分を最小にする。

.tsx importを許可するtsconfig変更も可能だが、他の多くのimportと同じ拡張子なしにそろえる。検査設定を緩めずに2箇所の原因を取り除く。

| Hook規約 | `app/(onboarding)/start.tsx` | 既存のeslint react-hooks/rules-of-hooks。`router.push('/question1')`は維持 |

小さい修正なので、実装の行位置をなぞるだけの新規テストは追加しない。既存の意味のある型・Hook検査を使う。実機の遷移確認は別に必要。
